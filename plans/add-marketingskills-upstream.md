# Add coreyhaines31/marketingskills as a third upstream

## Why
The bundle vendors mattpocock/skills and obra/superpowers. We want the 50 marketing skills from
`coreyhaines31/marketingskills` installed and synced nightly alongside them.

## Decisions
- **Same mechanism as the other two.** Register via `node sync/sync.mjs --add-upstream`, which
  gates on license and name clashes, then paste its snippet into the hand-written `upstreams`
  block of `sources.json`. No special-casing in `sync.mjs`.
- **Upstream id is `coreyhaines31`** (derived from the repo owner), so skills land in
  `skills/coreyhaines31/<name>/`.
- **`include: ["<root>"]`, no `exclude`, no `rewrite`.** Upstream is flat (`skills/<name>/SKILL.md`)
  and has no `<ns>:` cross-references.
- **No clashes at registration.** MIT licensed; no frontmatter `name` collides with an existing skill.
- **Router gets one short ruling, not a conflict resolution.** Marketing skills have no
  counterpart in the other two sets. Names that look alike (`research` vs `customer-research`)
  cover different domains.
- **Dangling upstream reference left alone.** `ad-creative` mentions `tools/clis/google-ads.js`,
  which does not ship in the vendored skill. Vendored output is never edited.

## Files
- `sources.json` — new `upstreams` entry; `plugin.description`, `keywords`, `version` 1.1.0 → 1.2.0.
- `skills/coreyhaines31/**`, `README.md`, `NOTICE`, `.claude-plugin/*` — generated by `npm run sync`.
- Hand-edited "two upstreams" wording: `CLAUDE.md`, `hooks/session-start`,
  `skills/matej/using-matej-skills/SKILL.md`, `skills/matej/xmmm1-skills-quickstart/SKILL.md`.
